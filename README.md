# Agenda Brief Builder

KIUA-2003, autumn 2026. For each item on a meeting agenda, the workflow searches the public
PDF attachments and collects every relevant passage **verbatim**, with physical page, printed
page label, section path and a `#page=N` link. The organiser reviews and approves each brief
in a local web UI. A brief is a **supplement to the full documents, never a replacement**.

Design rule: **the LLM selects segment IDs; code copies and checks the text** (V1–V7, §3.2 of
`project_plan.md`).

## Reproduce from a fresh clone

Requirements: Python 3.11+, [Ollama](https://ollama.com) running locally.

```powershell
# Windows (PowerShell)
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
ollama pull llama3.2:3b; ollama pull qwen2.5:7b
.\make.ps1 synthetic          # generate the synthetic edge-case PDFs
.\make.ps1 test               # unit tests (no model needed)
```

```bash
# Linux / macOS
make setup && ollama pull llama3.2:3b && ollama pull qwen2.5:7b
make synthetic && make test
```

Test document: put `algorithms.pdf` (Dasgupta, Papadimitriou, Vazirani, *Algorithms*, 2006
draft; not committed) in the project root.

Real meeting (`tests/cases/fylkesutvalget_2026-09-29/`): Fylkesutvalget, Innlandet
fylkeskommune, 29.09.2026. Download the møteinnkalling (one 1 319-page PDF with case papers
and all attachments) from
<https://prod01.elementscloud.no/publikum/920717152/DmbMeeting/1544> and save it as
`fylkesutvalget_2026-09-29.pdf` in the project root (not committed).

### A normal run

```powershell
.\make.ps1 run                                   # = python -m briefer run tests/cases/algorithms_synthetic/agenda.yaml
.\make.ps1 ui                                    # http://127.0.0.1:8000 — review, approve, export
```

Unattended: drop an `agenda.yaml` into `inbox/` and run `python -m briefer watch` (or
`watch --once` from Task Scheduler / cron every 5 minutes). Runs stop at *awaiting review*;
nothing is shared without approval.

Briefs are written to `runs/<run_id>/<meeting>/<style>/` as JSON, Markdown and HTML, with
`run_log.jsonl` (every stage, every item) and `run.json` (summary, tokens, timing).

### An evaluation run

```powershell
.\make.ps1 eval          # replay recorded LLM answers: deterministic, offline, free
.\make.ps1 eval-live     # call the configured models and refresh the replay cache
.\make.ps1 eval -Case algorithms_synthetic
```

Every case runs twice (as described, and titles only). Output: `eval/runs/<timestamp>/`
with `results.json`, `report.md` and the raw run logs.

## Configuration

| File | What |
|---|---|
| `config/llm.yaml` | provider + model per stage (S6, S8, judge), S8 strategy (`agent` / `pointwise`), `gdpr_approved` per provider |
| `config/budget.yaml` | token caps per item / run, currency cap |
| `config/sources.yaml` | fetch allowlist |
| `config/killswitch.yaml` | kill-switch thresholds |
| `.env` (from `.env.example`) | API keys, `BRIEFER_LLM_MODE`, `BRIEFER_DISABLED`, UI passphrase |

Stop everything: create a file named `STOP` in the project root, or set `BRIEFER_DISABLED=1`.

## Repository

```
config/      provider, budget, allowlist, kill switch, privacy
context/     prompts, rubric, glossary, injection policy, output schema, brief style
src/briefer/ agenda (S0) fetch (S1) parse (S2) privacy (S3) index (S4) xref (S5)
             understand (S6) retrieve (S7) agent (S8) assemble (S9) verify (S10) web (S11)
             llm/ (interface, adapters, cache, budget) safety (kill switch) pipeline cli
labels/      gold labels — never read by the pipeline
tests/       unit tests; cases/ (agendas + synthetic PDFs + rejected input)
eval/        harness, metrics, labelling helper, judge, runs/
docs/        labelling guideline, stress tests, meeting reports, prompt logs
```
