# Stress tests

Protocol for each perturbation (§10): (1) a test case injects it; (2) `eval-live` records the
failure; (3) the failure is traced stage by stage in `run_log.jsonl`; (4) a repair is
implemented; (5) the full evaluation is rerun to show the case passes with no regression;
(6) it is recorded here.

Classes chosen: **1 — input perturbation** and **4 — model variance** (open decision §15.5).

---

## Class 4 — model variance

### 4.1 Degenerate repetition in the S8 tool loop (llama3.2:3b) — found 24.10.2026

- **Perturbation:** a small local model (llama3.2:3b) in the S8 agent.
- **Failure observed:** items PS 3/26 and PS 4/26 ended `draft_incomplete` with
  `no valid JSON after retry: Unterminated string`.
- **Propagation:** S8 prompt contained `Search queries used: a; b; c…` → the model emitted
  `{"action": "search_index", "query": "a; b; c; a; b; c; …"}` and repeated the list until
  `max_tokens` (1 200) → JSON truncated → `complete_json` retried once with the same prompt →
  same failure → `LLMError` → item marked `draft_incomplete`. No incorrect text reached a brief.
- **Repair:** removed the query list from the S8 prompt; added `maxLength` to every free-text
  field of the S8 JSON schemas (Ollama compiles the schema into a decoding grammar, so the
  output cannot run on).
- **Regression evidence:** see the table in 4.2: no `Unterminated string` failures after the repair.

### 4.2 Model and strategy swap on S8 — 24.10.2026

Same agenda (`algorithms_synthetic`, 11 items), same S6 model (llama3.2:3b), same retrieval;
only S8 changed via `config/llm.yaml`. Gold: 47 provisional passages.

| llama3.2:3b | agent | described | 0.02 | 0.20 | 0.53 | 2/2 | after section expansion in S7 |

| qwen2.5:7b | pointwise | titles only | 0.40 | 0.18 | 0.45 | 1/2 | snow-clearing item gets extracts |

Edge-case meeting (synthetic nynorsk budget), qwen2.5:7b pointwise: recall 1.00, precision 0.80,
all gates correct (corrupt PDF, refused URL, personal-data document → `nothing_found`; closed
item skipped). No extract failed V1–V5 in any qwen run.

**Choice:** default `qwen2.5:7b` + `pointwise`, because §3.4 weights recall above precision.
The agent strategy is kept: it is 7× cheaper and more precise, and should be re-tested with a
stronger (GDPR-approved) model. Precision figures are a lower bound: the provisional labels
are too narrow (see docs/status.md).

**Reading:** with the 3B model the bottleneck moved between stages depending on strategy: the
agent selects almost nothing (it returns `nothing_found` even for RSA, whose candidates were
exactly the right pages), while the pointwise judge accepts almost everything, including
passages for the snow-clearing reject item. Neither meets §3.4.

### 4.3 V2 failures on machine-written notes

- **Failure observed:** 15 of 183 extracts removed by V2 in the pointwise run, all with
  `V2 note introduces numbers not in its extract`: the model wrote case numbers ("PS 4/26"),
  page numbers ("174") or section numbers into notes.
- **Repair:** (a) rubric now forbids case/page/section numbers in notes; (b) when V2 fails
  **only** because of the note, S10 drops the note (logged in `verification.notes_dropped`)
  and keeps the verbatim extract. V2 still holds: no number reaches the brief that is not on
  the cited page.

## Class 1 — input perturbation

Cases in `tests/cases/edge_documents/` (generated by `tests/cases/make_synthetic.py`) and
`tests/cases/rejected_input/`.

| Perturbation | Expected failure path | Repair in place | Status |
|---|---|---|---|
| Hidden (white) injection text in a PDF | S2 extracts it → S8 obeys it | S2 strips white and < 3 pt text (`hidden_text_removed` flag, count in run log) | unit test + edge case |
| Visible injection text in a paragraph | S8 obeys it → irrelevant extracts | S3 flags `injection`; untrusted-content delimiters in S8; kill switch 4 if selected | edge case |
| Corrupt PDF | S2 crashes the whole meeting | per-document isolation: attachment marked `unreadable`, item → `nothing_found` | edge case |
| URL outside allowlist | data fetched from anywhere | fetch refuses; attachment marked `unreadable` | edge case + unit test |
| Document dense with personal data | personal data reaches a brief | S3 excludes flagged segments; document above 5% held for review | edge case + unit test |
| Malformed `agenda.yaml` (missing `closed`, name field, wrong types, not YAML) | closed item processed | strict schema, no defaults for `closed`/`in_scope` | 4 rejected-input cases |
| Scanned page | silent recall loss | page flagged; listed in the brief as unsearchable | edge case + unit test |

Results per run are in `eval/runs/<timestamp>/report.md`.
